# Спецификация CoDuels

Помоги пользователю отделить обсуждение требования от его реализации. Пользователь прорабатывает спецификацию в одной сессии Codex, а выполнение задачи поручает другой.

1. Прочитай корневой `AGENTS.md` репозитория CoDuels, `AGENTS.md` владельца изменения и применимые проектные навыки. Сверь предлагаемое поведение с кодом и документацией процесса. Если детали существенно влияют на результат и не выводятся из контекста, уточни их до публикации; остальные решения прими самостоятельно.
2. Определи репозиторий-владелец среди CoDuels и его компонентов. Создай GitHub Issue именно в нём. Не начинай реализацию и не переводи задачу в In Progress в рамках работы над спецификацией.
3. В описании задачи укажи контекст и причину, цель, краткое предполагаемое решение и проверяемый Definition of Done. Различай текущее и требуемое поведение. Сохрани принятые пользователем решения и важные ограничения, не добавляя необоснованных требований.
4. Добавь Issue в GitHub Project **CoDuels**. Установи поля проекта **Status: Backlog**, **Sprint: без значения**, **Component: компонент, которому принадлежит изменение**, **Type: подходящий тип задачи, выбранный самостоятельно из актуальных вариантов проекта**. Это поля проекта, а не лейблы репозитория. Проверь сохранённые значения всех полей и связь с проектом после создания.
5. Отдай пользователю ссылку на Issue. Если операция с проектом или его полями недоступна, явно укажи, что именно не удалось, и оставь ссылку на созданную задачу.

Если задача затрагивает несколько компонентов, выбери основной репозиторий по владельцу поведения и отрази остальные зависимости в спецификации. Не создавай дополнительные задачи без необходимости.
